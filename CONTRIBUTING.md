# Участие в разработке

Начните с [инструкции разработчика](docs/development.md). Для запуска нужны macOS, Node.js 22+, Chrome и Docker Desktop либо Colima с Docker CLI и Compose.

## Исправления и pull request

1. Опишите проблему и ожидаемое поведение в issue или непосредственно в небольшом pull request.
2. Внесите минимальное изменение в соответствующий компонент. Для ошибок генерации сначала выясните, где причина: интерфейс, MCP-мост, backend или ответ Google.
3. Запустите проверки затронутого компонента и добавьте проверку поведения, если меняется существенная логика.
4. Проверьте diff на секреты, личные пути, аккаунты и runtime-данные.
5. В pull request укажите, что изменилось, как воспроизвести исходную проблему и какие проверки выполнены. Не выдавайте тесты с заглушками за проверенную генерацию Google.

Для заметного изменения интерфейса приложите снимок с тестовыми данными. Не делайте платную генерацию необходимым условием обычных тестов. Если проверка требует кредитов, сообщите это до ее выполнения.

## Структура

- `app/` — Electron, интерфейс, управление аккаунтами и локальный MCP-мост.
- `backend/` — vendored Flow2API с локальными изменениями; сохраняйте исходную лицензию.
- `extension/` — дополнительный путь синхронизации сессий из обычного Chrome.
- `skills/flow-studio/` — инструкция для агента; синхронизируйте ее с реальными схемами MCP.
- `docs/` — пользовательские и технические инструкции.

Не добавляйте механизмы автоматической смены модели или скрытого повтора платной генерации. `requestId` должен сохраняться при повторе одного и того же принятого запроса. Сообщения об ошибках должны сохранять технический код и различать неуспешную задачу и неизвестный результат из-за разрыва связи.
