# Flow Studio

Operate the installed Flow Studio app through its MCP tools. It owns the running backend, Google sessions, job history, and local media. The bridge can launch the app; do not start a second backend or call Google endpoints directly.

The engine runs while Flow Studio is open. Closing its window with × or quitting with `⌘Q` exits the app and stops the engine; minimizing keeps it open. MCP does not keep a standalone backend after exit, but a later call can reopen the app. If the user closes Flow Studio to stop work, stop polling.

## Route and discover

Use this route when the user chooses Flow Studio or invokes `$flow-studio`. Keep generic image requests on the built-in `image_gen` route. Do not silently switch routes after failure.

Discover tools ending in the `flow_studio_*` names below. A session may cache an older schema: reconnect its MCP client to load new tools, or use the same app bridge through [references/cli.md](references/cli.md). A full Codex restart is not needed for that fallback.

Read `flow_studio_status`: the current bridge reports `apiVersion: 3` and features `generation-settings`, `prepare-generation`, `explicit-methods`, and `isolated-browser-generation`. If the session exposes an older schema, use the CLI fallback or reconnect MCP before using new fields. Then call `flow_studio_list_models` with the requested filters. Use current exact model IDs and metadata, never remembered IDs. Filters include `kind`, `method`, `family`, `durationSeconds`, `aspectRatio`, `resolution`, plus legacy `mode` and `query`. Methods are `image`, `text`, `ingredients`, `frames`, `edit`, and `extend`.

Inspect `family`, `methods`, `durationSource`, `resolution`, `inputsByMethod`, `fileLimits`, and input limits. `resolution: "standard"` is a real default. Edit reports `durationSource: "input_video"`. Legacy `mode` remains unchanged: image models report `mode: "text"` while using method `image`; video `mode: "references"` maps to ingredients. Ordinary Omni supports both `text` and `ingredients`.

Catalog presence and preflight do not prove active account access or enough credits. Preserve the user's model and settings. An absent, ambiguous, or unavailable combination fails without fallback; explain the returned state and obtain the user's choice before changing it. Settings resolution collapses only the known same-version aliases listed in the generation reference; an exact `model` request preserves its chosen catalog ID.

## Isolated background browser

Supported Nano Banana image IDs, Omni 1.2 Flash text/ingredients/Frames/Edit IDs, and standard Veo 3.1 IDs use the app-owned browser through standard `generate`. Read each exact model’s `generationEngine` in the live catalog. Nano Banana 2.1/Pro 2K/4K use explicit download upscales; Lite remains standard-only. Veo 4s/6s must fail before submission if the requested duration cannot be verified. Omni 1.2 Edit uses Flow Agent in the same app-owned browser, preserving the exact account, model, prompt, source video and image order. Agent prepares one proposal for one video. Before one Approve action, the app verifies the proposal, persists its private receipt and crosses the same authorized-spend boundary; there is no automatic reapproval, account rotation or paid fallback. The installed-app Omni 1.2 Edit pipeline through Flow Agent is verified with a source video and two distinct images in exact order: original prompt, one proposal, one Approve for 36 credits, waiting, bound-History verification, download and save without manual recovery. The job completed in 279 seconds; the MP4 is 720×1280, 9:16, H.264/AAC, 10.026667 seconds. Separate no-image-reference and two-image jobs also passed receipt recovery without another generation. A separate installed-app portrait Omni 1.2 Edit 360p case without image references completed with one proposal, one Approve for 4 credits, waiting, original-size download and save: 360×640 H.264/AAC at 24 fps, 3.029333 seconds. The job completed in 219 seconds and preserved source dimensions and duration. These checks cover the stated cases; 360p Edit with image references, other aspects and durations are not claimed verified. Keep explicit IDs and methods; extend and unsupported variants retain their catalog route. A browser failure never falls back to the server or changes accounts automatically.

The browser uses a Google profile connected through Flow Studio. `list_accounts` may report `browserReady:false`; reconnect that account once in the app, then the session persists. This mode does not use desktop focus, Accessibility, Screen Recording, or the user's ordinary Chrome. Closing the app stops its owned browser and local waiting; Google may still complete an accepted task.

Use optional `accountId` from `list_accounts` to pin one active account in `prepare_generation`/`generate`. Omission selects one eligible account once. Use `flow_studio_inspect_isolated_browser` with `{accountId}` to check login and project without uploads or spending. Preparation defaults to local validation only. Optional `checkBrowser:true` with an explicit `accountId` performs a no-spend managed-browser check: uploads the selected image references, frame roles, or Edit source video to Google and verifies the owned composer/settings before clearing it, and releases the browser. It never submits or creates a job; do not automatically retry this upload check. Returned `generateArguments` excludes `checkBrowser`. The bridge waits up to 600 seconds for `checkBrowser:true`, including user rights consent; ordinary local preparation keeps 120 seconds. Set the MCP client timeout accordingly. A timeout never authorizes an automatic upload retry. Standard generation performs upload, one submission, observation, download and durable history.

On a first upload, Google may show “Rights to use this image” or separate source-video rights terms. Flow Studio displays the exact terms and account in its own confirmation dialog; only the user accepts or cancels. Never pre-accept rights terms or infer acceptance from upload/generation authorization. Cancellation stops that upload. Honor explicit consent already given for the same account and terms in the current session. This consent never submits generation or authorizes credit spend.

Before submission, `FLOW_UI_TIMEOUT` at `account-button` or `composer-ready` can reflect a product announcement or an empty expanded Agent panel, including an off-viewport layout. The app dismisses only the recognized Omni 1.2 announcement and closes only one verified empty Agent panel; nonempty drafts and references stay untouched. Other onboarding, rights and terms remain user actions. Use a no-spend isolated-browser inspection on the same account for a persistent readiness error; never retry generation diagnostically. See [project readiness](references/generation.md#project-readiness).

Legacy `prepare_browser`/`native_prepare` and `submit_browser`/`native_submit` are blocked with `VISIBLE_WATERMARK_ROUTE_UNVERIFIED`, including old tokens: no input uploads, preparation token or paid video submission. This route cannot verify official `Visible watermarking: Off`. Only legacy `inspect_browser`/`native_inspect` and `cancel_browser_preparation`/`native_cancel` remain usable for diagnosis and releasing old preparation. They are not a generation fallback. Read [references/native-browser.md](references/native-browser.md) for these limits.

## Visible-watermark default for new videos

New videos require verified official Google `Visible watermarking: Off` by default. Supported browser Omni/Veo/Edit paths check it before input uploads and again before the paid action; an available switch is turned Off and reopened to confirm persistence. Missing, ambiguous, locked or unsaved Off blocks the new request before credits. Server and legacy video submission routes without this verification fail with `VISIBLE_WATERMARK_ROUTE_UNVERIFIED`; never fall back, rotate accounts or change region to evade the policy.

`VISIBLE_WATERMARK_REQUIRED` carries Google's explicit mandatory reason (observed: `Visible watermarking is required in your region`). `VISIBLE_WATERMARK_UNVERIFIED` means Off could not be proved. Preserve the exact returned code/reason, stop before spend and explain the account-specific state; do not infer a global region/model rule. Default local preparation leaves this unchecked. Video `checkBrowser:true` applies/verifies the official account setting without generating or spending generation credits. This account-wide change can affect future work outside the task; image generation itself is unchanged. Read-only recovery of existing media does not alter the setting. Do not replace official verification with removal of visible marks or SynthID from existing files.

## Preferred video model

For a new video when the user has not chosen a model, prefer **Omni 1.2 Flash**. Select an exact compatible ID from live `list_models`, respecting method, aspect ratio, duration, resolution and input roles; catalog `preferred` metadata reflects this policy. Never invent IDs by replacing 1.1 with 1.2 or treat an official Gemini API ID as an internal Flow ID.

Omni 1.1 is not preferred. Preserve an explicit user selection, including Omni 1.1 and legacy aliases. Never migrate history, drafts, saved selections, prepared `generateArguments` or an identical request replay to the new preference. Image generation keeps its separate model choice.

If compatible Omni 1.2 is absent or unavailable, report the reason and returned code/message. Do not silently fall back to Omni 1.1, Veo or another model. A configured preference does not prove backend support and does not authorize a paid test.

For reference-bearing Edit requests, a separate visible Agent control turn preserves the original creative prompt and image order; it contains no attachments and must not request generation/approval. It does not authorize a paid approval or rewrite the user prompt. See the generation reference for the exact two-turn binding.

## Prepare, generate, save

1. Preserve the user's prompt, model/settings, input order, and frame roles. Resolve inputs to absolute local file paths. If an attachment lacks an accessible local path, ask for the file or its path; do not invent paths or fetch arbitrary remote images.
2. Call `flow_studio_prepare_generation` with the prompt, inputs, and exactly one of `model` or `settings`. With an exact `model`, optional outer `method` makes the input method explicit. With `settings`, put the method inside that object and omit outer `method`. See [references/generation.md](references/generation.md) for settings and examples.
3. Read the resolved model, method, settings, input counts, and `checks`. Default preparation validates absolute paths, formats, regular files, sizes, limits, and roles without decoding media, probing duration, upload, generation, job creation, persistence, or credit spend. Only when a browser/upload check is requested, add `checkBrowser:true` and explicit `accountId`; this uploads the supported model’s image references, frame roles, or Edit source video to Google and checks/clears the owned preparation without generating. Check `checks.browser: "passed"`, `checks.upload`, and `browserCheck.submitted:false` / `cleared:true`; it still does not prove paid generation acceptance. It needs no `requestId` or `confirmCreditSpend`. A valid result reports `localFiles: "passed"`, `accountAccess`/`credits: "not_checked"`, and `videoDuration: "checked_at_submission"` for a source video or `"not_applicable"` otherwise. It does not guarantee Google acceptance or compliance with the source video's model-specific duration limit.
4. Preserve returned `generateArguments` verbatim: it pins the exact model ID, explicit method, prompt, and original paths. For this user-authorized generation, add a fresh UUID `requestId` and `confirmCreditSpend: true`, retain the full request, then call `flow_studio_generate`. Do not ask again for the same authorized spend. Setup, browsing, preflight, and diagnostics alone do not authorize generation.
5. Retain `jobId`. Use `flow_studio_wait_job` with `timeoutSeconds` up to 30, or `flow_studio_get_job`, until complete. A wait or transport timeout does not prove failure. Stop when the user requests it or closes the app to stop work.
6. Save successful media with `flow_studio_save_result`. Create the parent directory first. Prefer the task's user-facing `outputs/` unless the user chose another location; use an absolute path, correct extension, and `overwrite: false` unless replacement was authorized. Link the saved file and show local image/video media inline when supported. Open Finder with `flow_studio_open_result_folder` only when requested.

`generate` also accepts exactly one of `model` or `settings`, under the same rules. Prefer prepared `generateArguments` so model resolution stays fixed between checking and spending.

| Method | Inputs |
| --- | --- |
| `image` | Optional `referencePaths` in user order |
| `text` | No reference, frame, video, or source fields |
| `ingredients` | At least one image in `referencePaths`; ordinary Omni allows up to seven |
| `frames` | `startFramePath` required; optional `endFramePath` only when supported |
| `edit` | One `videoPaths` source plus optional image `referencePaths` |
| `extend` | Verified `sourceVideoId` only |

Frame paths carry separate roles. Never pass `referencePaths` as frames, infer roles from upload order, or send an end frame alone. If roles are unclear, ask before spending. End is required when the model reports `minImages: 2`. Cross-method inputs are rejected. Exact ordinary Omni without outer `method` infers `ingredients` when references exist and `text` otherwise; explicit `ingredients` always requires a reference.

Images: PNG, JPEG, WebP, GIF, at most 20 MB each. Image generation accepts up to five images, Veo ingredients up to three, ordinary Omni up to seven. Omni Edit accepts one MP4/MOV/M4V up to 100 MiB, plus up to five images. Read `fileLimits.video.maxDurationSeconds`: Omni 1.2 Edit allows 15 seconds; Omni 1.1 Edit keeps 10. For the current Omni 1.2 browser Edit implementation, source geometry must exactly match the requested mode: 360×640 or 640×360 at 360p; 720×1280 or 1280×720 at standard 720p. Mismatched geometry fails before upload; the app does not resize or reinterpret the selected model. Duration is checked before upload/submission. The owned Agent proposal must quote the exact amount calculated for the selected mode using the source duration rounded up to whole seconds; Omni 1.2 seconds above ten count double. The direct-editor precheck for 720p follows its menu rounding, while Agent rounds duration up: the previously verified 10.026667-second source quoted 36 credits in Agent versus 30 in the direct editor. This is not a doubled budget or permission to change models. Matching cost does not prove output resolution; exact dimensions and duration are checked before success. Agent recovery saves a typed IMAGE preview of the source video and binds its resource to the original scene, exact prompt and ordered images in the selected History entry. The IMAGE preview is not a Google video ID; the app does not invent a /video/ identifier. Recovery reads the existing result without uploading inputs, creating another proposal or clicking Approve. For supported observation errors after submission, the app releases its browser and resumes reading the same job once from its private receipt. Agent recovery additionally verifies account, project, model, full prompt, source scene and image order. Cancellation, confirmed rejection or receipt mismatch blocks this transition. Recovery performs no input uploads, creates no proposal or new job, and never clicks Approve; it incurs no new credit charge. Another observation failure retains the unknown outcome. For 360p, the app selects and verifies 360p, aspect and x1 in ordinary Flow settings before source upload and again before starting Agent. A separate control instruction fixes exact 360p and aspect, source duration and the unchanged creative prompt, prohibiting 720p, upscaling or resizing. The owned Agent proposal must match the selected-mode calculation exactly: the observed 3.029333-second source requires 4 credits when rounded up. A missing, ambiguous or inconsistent proposal stops before Approve. Matching cost does not prove output resolution; downloaded dimensions and duration are checked separately. Do not switch mode, resize, retry or spend diagnostically. Pass paths, never base64. MCP path fields use the same native format/size checks as app file selection and drag-and-drop; MCP has no drag-and-drop/File API.

Respect `inputsByMethod`, `fileLimits`, `minImages`, `maxImages`, `maxVideos`, `maxReferences`, `supportsVideoReferences`, `supportsStartFrame`, `supportsEndFrame`, and `requiredTier`. Omni 1.2 frames allow an optional end frame at 3–10 seconds; 11–15 seconds accept only a start frame and require Pro or Ultra. Veo 4s/6s requires Ultra; change to 8s only when it matches the request or the user chooses it.

For extension, read the existing job and use chosen `media[index].mediaGenerationId` as `sourceVideoId`. Local `jobId` is not Google's source video ID. If no verified media ID exists, obtain it from the user.

## Resume, retry, stop

Use `flow_studio_list_jobs` and `flow_studio_get_job` to resume work. Do not generate again because a result has not appeared.

For an isolated-browser job with unknown outcome, use `flow_studio_recover_job` with the existing `jobId` without resubmitting. It reads the durable receipt, verifies the pinned account/project, and binds exact full prompt text, ordered references and output poster to one selected semantic History entry. The same tuple is rechecked before the entry’s own button and aria-controlled download menus are used. Missing, ambiguous or changed bindings fail closed. Existing two-reference image and Veo 720p downloads and original receipt-based recovery passed this read-only path without another generation. The installed-app Omni 1.2 Edit pipeline through Flow Agent is verified with a source video and two distinct images in exact order: original prompt, one proposal, one Approve for 36 credits, waiting, bound-History verification, download and save without manual recovery. The job completed in 279 seconds; the MP4 is 720×1280, 9:16, H.264/AAC, 10.026667 seconds. Separate no-image-reference and two-image jobs also passed receipt recovery without another generation. A separate installed-app portrait Omni 1.2 Edit 360p case without image references completed with one proposal, one Approve for 4 credits, waiting, original-size download and save: 360×640 H.264/AAC at 24 fps, 3.029333 seconds. The job completed in 219 seconds and preserved source dimensions and duration. These checks cover the stated cases; 360p Edit with image references, other aspects and durations are not claimed verified. For supported observation errors after submission, the app releases its browser and resumes reading the same job once from its private receipt. Agent recovery additionally verifies account, project, model, full prompt, source scene and image order. Cancellation, confirmed rejection or receipt mismatch blocks this transition. Recovery performs no input uploads, creates no proposal or new job, and never clicks Approve; it incurs no new credit charge. Another observation failure retains the unknown outcome. No upload, Generate click, new job, new UUID, or credit confirmation. Follow the same job with wait/get. `BROWSER_RECEIPT_MISSING` means manually inspect the original Flow task; never invent a receipt or resubmit. `recoveryAvailable` and `recoveryBlockedReason` describe the app action.

If a generate response is lost, inspect history, then retry only with the **same UUID, identical arguments, and unchanged files**. The bridge deduplicates while the job remains among the latest 100 retained jobs, across restarts. Resolve an older request's outcome before retrying it. A new UUID means a new generation and potential new charge. Never change model, settings, prompt, route, or inputs automatically after failure.

Jobs report `accountId`/`accountEmail` when selected, and `retryAvailable`/`retryBlockedReason`. Account summaries may report `cooldownUntil`, `cooldownRemainingSeconds`, `cooldownResetAllowed`, `lastGenerationError`, and `lastGenerationErrorAt`. Attributed account/provider failures pause that account locally for 30 minutes across restarts; local upload preparation errors and content rejections do not penalize it. Expiry never resubmits a job. Do not rotate accounts or automatically retry `PUBLIC_ERROR_UNUSUAL_ACTIVITY`.

The app's **Повторить генерацию** button reuses exact private cached inputs and the original account; cache retains at most 20 jobs / 512 MiB. Retry remains a UI action. Explicit manual cooldown reset is available through the app or `flow_studio_reset_account_cooldown` with exact `accountId`. Unknown outcomes, cancellation, content rejection, missing cached inputs or unavailable original accounts block replay. A local cooldown reset does not lift Google's restrictions; manual reset can clear this app-local timer for any error, including unusual activity, while preserving last error and manual disabled state. It does not change Google restrictions; never reset automatically or start generation as a side effect.

`PUBLIC_ERROR_UNUSUAL_ACTIVITY` confirms rejection of this submission, not an account-wide block. A working ordinary Flow UI and a refused server-side request can coexist. Preserve the RPC ID, model, submitting account and failure stage. A provider returning a verification token does not prove Google accepted generation; cooldown is containment, not a compatibility fix.

On failure, preserve returned error/message and technical code. Distinguish confirmed failed jobs from unknown transport outcomes; do not infer moderation from an empty response. Offer a next step without starting another paid request. Never use paid generation as a diagnostic.

`FLOW_UPLOAD_BROWSER_TIMEOUT`, `FLOW_UPLOAD_BROWSER_UNAVAILABLE`, `FLOW_UPLOAD_BROWSER_ERROR`, and `FLOW_UPLOAD_VERIFICATION_EMPTY` distinguish local upload preparation failures; retain the exact code. They identify a failure stage, not proof that Google rejected the account or that a fix worked. The legacy `Failed to obtain reCAPTCHA token for image upload` is a local pre-upload failure: the failed image was not uploaded and this attempt did not reach generation submission; earlier input uploads may have completed. It does not prove quota exhaustion, model rejection, or expired login. Do not retry generation as a diagnostic or change account/model/inputs. Ask whether the same file attaches in the ordinary Flow browser UI without generating; any Google verification is completed by the user. The app's “Open Flow in browser” button is a manual handoff, not an automated CAPTCHA recovery or proof that app upload works.

`PUBLIC_ERROR_MINOR` is an explicit Google rejection with no documented exact public definition. It alone does not identify the input or prove anyone's age. Do not confuse it with `PUBLIC_ERROR_USER_MINOR`, `401`, or quota errors. Read the same task's Flow web UI message if available. Do not retry identical rejected inputs, rotate accounts, change references, or rewrite the prompt automatically. Google does not support editing uploaded videos of identifiable minors; misclassified adult content belongs in its feedback/support flow.

`flow_studio_cancel_job` stops the app request; Google may still complete or charge it. Quitting also stops local waiting. Check Flow for an accepted job's outcome before retrying; do not automatically resubmit failed or cancelled jobs.

## Accounts

Use status or `flow_studio_list_accounts` for account summaries and reported credits. Explicit `flow_studio_set_account_active` takes `{accountId,enabled}` to change participation; `flow_studio_check_account` takes `{accountId}` to validate the saved session and identity. Connection checks use the app’s managed synchronization and saved-session verification; the participation toggle changes only the requested enabled state. `flow_studio_check_enabled_accounts` takes `{}` for the same serial check across enabled accounts, skipping disabled accounts and reporting per-account errors. None generates, enables an account automatically, or clears cooldown. Do not enable or rotate an account automatically after failure; keep the user’s explicit disabled state. For a new account, call `flow_studio_begin_google_login` without `accountId`; pass a known `accountId` only to reconnect it. The user signs in through Google's browser UI, then call `flow_studio_complete_google_login`; cancel abandoned sign-in with `flow_studio_cancel_google_login`.

Never request or read passwords, cookies, session tokens, or bridge secrets. The app handles credentials. Account summaries do not establish model entitlement.
