# MCP и управление через агента

[← README](../README.md)

MCP-сервер работает через `stdio` и управляет установленным Flow Studio. Он использует те же аккаунты, модели и историю, что и интерфейс. Не запускайте отдельный Flow2API для агента.

Мост может запустить установленное приложение при вызове инструмента. Движок работает, пока открыто Flow Studio: закрытие окна кнопкой × или выход через `⌘Q` останавливает его, сворачивание окна — нет. Сам MCP-сервер не держит движок работающим после выхода из приложения. Следующий вызов инструмента может снова открыть Flow Studio. Если пользователь закрыл приложение, чтобы остановить работу, агент прекращает опрос.

## Подключение

Нужны установленный Flow Studio и Node.js 22.12 или новее.

1. Установите зависимости из корня репозитория:

   ```bash
   npm ci --prefix app
   ```

2. Запустите приложение и убедитесь, что движок подключен. Завершите первый вход в Google через интерфейс.
3. Добавьте MCP-сервер в настройки вашего клиента. Если клиент принимает формат `mcpServers`, используйте пример ниже; замените абсолютный путь на свой.

   ```json
   {
     "mcpServers": {
       "flow-studio": {
         "command": "node",
         "args": ["/absolute/path/flow-studio/app/mcp-server.cjs"]
       }
     }
   }
   ```

4. Если клиент не находит `node`, укажите абсолютный путь к нему из `command -v node`. GUI-приложения могут использовать другой `PATH`, чем терминал.
5. Перезапустите подключение MCP в клиенте. Проверьте доступность через `flow_studio_status` и `flow_studio_list_models`. Текущий сеанс может хранить старую схему инструментов: переподключите MCP-клиент для обновления или используйте тот же мост через CLI ниже. Для CLI не нужен полный перезапуск Codex.

Для Codex CLI тот же сервер можно зарегистрировать командой:

```bash
codex mcp add flow-studio -- node /absolute/path/flow-studio/app/mcp-server.cjs
```

Используйте команду настройки, поддерживаемую установленной версией клиента. Для первого запуска задайте тайм-аут инструмента не меньше 300 секунд, если клиент это позволяет. Если Docker еще собирает образ, дождитесь готовности в приложении и повторите чтение статуса.

Для внешнего MCP-клиента используйте адаптер из исходников, как показано выше. Код внутри `app.asar` готового приложения не является обычным файлом, который внешний Node.js может открыть напрямую.

Не добавляйте API-ключ, Google cookies или секрет моста в конфигурацию MCP. Мост получает локальные данные подключения самостоятельно. Если автозапуск приложения не сработал, откройте Flow Studio вручную.

## Стабильный адаптер вне облачной папки

Если исходники лежат в iCloud Drive и MCP зависает при чтении зависимостей, распакуйте MCP-архив релиза в локальную папку вне синхронизации, например `~/Applications/Flow-Studio-MCP`, и установите его зависимости по lockfile. Не указывайте внешнему Node.js путь внутри `app.asar`.

```bash
cd "$HOME/Applications/Flow-Studio-MCP"
npm ci --ignore-scripts
node mcp-server.cjs --list-tools
node mcp-server.cjs --call status '{}'
```

MCP-архив включает полный навык `skills/flow-studio/`: `SKILL.md`, метаданные `agents/` и справочники `references/`. Для Codex скопируйте эту папку в `${CODEX_HOME:-$HOME/.codex}/skills/flow-studio`, предварительно сохранив свои изменения, если навык уже установлен. Навык не заменяет подключение MCP-сервера.

В MCP-конфигурации укажите абсолютный путь к этому `mcp-server.cjs`. Переподключите MCP-клиент, чтобы перечитать 24 инструмента; для CLI полный перезапуск Codex или Flow Studio не нужен. Проверка всех включенных аккаунтов последовательная и может занять несколько минут: тайм-аут инструмента 600 секунд соответствует ограничению адаптера. Истечение клиентского тайм-аута не запускает новый запрос и не означает, что проверка в приложении остановилась.

Обновляйте приложение и MCP-адаптер вместе. Перед видеогенерацией и проверкой видео в браузере адаптер проверяет, что подключенное приложение сообщает `video-watermark-selection`. Ошибка `FLOW_STUDIO_UPDATE_REQUIRED` останавливает запрос до запуска или загрузки исходников.

## Автоматический фоновый маршрут

Стандартный `flow_studio_generate` автоматически использует отдельный браузер Flow Studio для поддерживаемых Nano Banana, Omni 1.2 Flash и стандартных Veo 3.1. Omni 1.2 сохраняет методы `text`, `ingredients` и `frames` с максимум семью изображениями. Отдельные `prepare_browser` и `submit_browser` для этого не нужны. Окна обычного Chrome, разрешения Accessibility и Screen Recording не используются. Omni 1.2 Edit подключен к фоновому маршруту; для него проверены две задачи без дополнительных изображений в 720p, 9:16, около 10 секунд с отдельным восстановлением результата; непрерывное завершение с двумя изображениями в указанном портретном 720p сценарии проверено. Extend и неподдерживаемые варианты сохраняют прежний маршрут.

Смотрите `generationEngine` и `visibleWatermarkVerification` в `list_models`. Поддерживаемые видеомодели проверяют настройку в `isolated-browser`. Серверные и прежние видеомаршруты без проверки блокируют отправку. Новые задачи сохраняют `generationEngine`. Наличие маршрута само по себе не подтверждает доступ аккаунта.

`list_accounts` возвращает `browserReady`. При `false` выполните **Войти заново** для того же аккаунта в Flow Studio. `flow_studio_inspect_isolated_browser` принимает только `{"accountId": 7}`, проверяет вход и проект и обновляет локальную сводку о возможности управлять водяным знаком. Используйте реальный ID из списка аккаунтов. Проверка проходит без загрузки файлов и расхода кредитов.

В `prepare_generation` и `generate` можно передать необязательный положительный целый `accountId`. Подготовка сохраняет его в `generateArguments`, но не проверяет доступ аккаунта. Без поля приложение один раз выбирает доступный включенный аккаунт. После ошибки аккаунт и движок не меняются автоматически. По умолчанию `prepare_generation` проверяет только локальные исходники. Для запрошенной проверки загрузки добавьте `checkBrowser:true` и явный `accountId`: ингредиенты будут загружены Google в управляемом браузере, параметры и текст проверены, принадлежащий проверке черновик очищен, браузер закрыт. Генерация не нажимается, задача и списание кредитов не создаются. Ответ содержит `checks.browser: "passed"`, `checks.upload` и `browserCheck` с `submitted:false`, `cleared:true` и числом изображений. Не повторяйте такую проверку автоматически после ошибки связи. В `generateArguments` флаг не попадает; `generate` его не принимает. Локальная подготовка ожидает ответ до 120 секунд; явный `checkBrowser:true` — до 600 секунд, включая ответ пользователя на условия Google. MCP-клиенту нужен соответствующий тайм-аут. Истечение ожидания не разрешает автоматический повтор загрузки.

При первой загрузке Google может показать «Rights to use this image» — подтверждение прав на изображение. Flow Studio покажет текст Google и адрес аккаунта в своем диалоге. Подтверждает пользователь; отмена останавливает загрузку. Приложение не принимает эти условия автоматически, а согласие на загрузку не запускает генерацию и не разрешает расход кредитов.

Точные стандартные Nano Banana 2.1, Nano Banana 2 Lite и Nano Banana Pro в форматах 16:9, 9:16, 1:1, 4:3 и 3:4 подключаются к фоновому маршруту. В установленном приложении проверены новый запрос с двумя разными референсами (JPG 768×1376) и восстановление изображения без референсов (1024×1024). Это не проверка всех пятнадцати вариантов. Для Nano Banana 2.1 и Pro точные варианты 2K/4K используют явный upscale при скачивании через Flow; качество генерации не подменяется молча. Nano Banana 2 Lite сохраняет стандартное разрешение. Существующий портретный результат Nano Banana 2.1 успешно скачан через 2K Upscaled в 1536×2752; это проверка данного скачивания без новой генерации, а не всех вариантов 2K или 4K. Google может запросить отдельное согласие на права исходного видео. Оно не запускает генерацию; подтверждены две задачи Agent Edit без дополнительных изображений в 720p, 9:16, около 10 секунд с отдельным восстановлением; другие сочетания проверяются отдельно.

## Видимый водяной знак видео

`prepare_generation` и `generate` принимают необязательный `videoWatermark` на верхнем уровне рядом с `model` или `settings`. По умолчанию `"with"` требует подтвержденное `Visible watermarking: On` в Google Flow. Выбирайте `"without"` только по явному запросу пользователя. Для него требуется подтвержденное `Visible watermarking: Off`. Запросы изображений отклоняют это поле.

Фоновый маршрут проверяет выбранное состояние перед загрузкой исходников и перед Generate или Agent Approve. Если текущий параметр отличается, приложение использует штатный переключатель и проверяет сохранение. Настройка действует на весь аккаунт Google Flow. Для существующих файлов используются обычное скачивание и восстановление прежней задачи с сохранением водяных знаков и SynthID.

Сводки `status` и `list_accounts` возвращают сохраненное `visibleWatermarkCapability`. `required` означает, что Google требует знак. `optional` означает, что Google разрешает выбрать состояние. `unknown` означает, что возможность отключить знак пока не подтверждена. Запрошенные `check_account` и `check_enabled_accounts` читают эту возможность через управляемый браузер без изменения настройки, загрузки исходников и расхода кредитов. При `"without"` автоматический выбор учитывает только доступные аккаунты с `optional`. Для закрепленного аккаунта с `unknown` проверьте его через `check_account` или явно запрошенный `checkBrowser:true`. При `required` сохраните выбранные аккаунт и режим и сообщите причину отказа.

Локальная подготовка возвращает `checks.visibleWatermark: "not_checked"` и выбранный `videoWatermark` в `generateArguments`. При явной проверке `checkBrowser:true` ответ содержит `checks.visibleWatermark` и `browserCheck.visibleWatermark` со значением `"on"` или `"off"`. Такая проверка может поменять настройку аккаунта и загружает переданные исходники без отправки генерации. Неподтвержденное состояние останавливает отправку.

При отказе сохраните точный код и сообщение. `VISIBLE_WATERMARK_REQUIRED` означает обязательный знак для выбранного аккаунта. `VISIBLE_WATERMARK_UNVERIFIED` означает, что нужное состояние или возможность отключения не подтверждены. `VISIBLE_WATERMARK_ACCOUNT_UNAVAILABLE` означает, что автоматический выбор не нашел подходящего подтвержденного аккаунта для `"without"`. `VISIBLE_WATERMARK_ROUTE_UNVERIFIED` означает, что маршрут не проверяет настройку. Для любого из этих кодов не меняйте модель, аккаунт или режим автоматически.

## Порядок генерации

1. Прочитайте `flow_studio_status`. Текущий мост сообщает `apiVersion: 3`, возможность `video-watermark-selection` в `features`, `videoWatermarkDefault: "with"` и `videoWatermarkModes: ["with", "without"]`. Если сеанс хранит старую схему, переподключите MCP или используйте CLI. Затем отфильтруйте `flow_studio_list_models` по запросу пользователя и используйте точные `id`, `family` и ограничения каталога.
2. Вызовите `flow_studio_prepare_generation` с текстом, исходниками и ровно одним селектором: `model` или `settings`. По умолчанию подготовка проверяет локальные форматы, размеры и роли, но не загружает файлы, не создает генерацию или задачу и ничего не сохраняет. Поля `requestId` и `confirmCreditSpend` ей не нужны.
3. Прочитайте результат проверки и сохраните возвращенные `generateArguments` без изменений вместе с `videoWatermark` для видео. Для запрошенной пользователем генерации добавьте новый UUID в `requestId` и `confirmCreditSpend: true`, сохраните полный запрос и вызовите `flow_studio_generate`.
4. Сохраните полученный `jobId`. Вызывайте `flow_studio_wait_job` с `timeoutSeconds: 30`, пока `done` не станет `true`, либо проверяйте `flow_studio_get_job`.
5. Для успешной задачи вызовите `flow_studio_save_result`. Родительская папка `outputPath` должна существовать. Поле `index` выбирает результат с нуля; по умолчанию используется первый. Существующий файл не перезаписывается без `overwrite: true`.
6. Верните пользователю сохраненный файл. Открывайте Finder только по запросу пользователя.

Успешная подготовка возвращает `valid`, сведения о точной модели, `method`, нормализованные `settings`, счетчики `inputs`, `generateArguments` и `checks`. В проверках `localFiles` имеет значение `passed`, `videoDuration` — `checked_at_submission` при наличии исходного видео и `not_applicable` без него, `accountAccess` и `credits` — `not_checked`. При локальной проверке проверяются абсолютные пути, форматы, наличие обычных файлов, размеры и роли; декодирование медиа и проверка длительности не выполняются. Доступ аккаунта, баланс и принятие запроса Google подготовка не подтверждает.

Запрос пользователя на конкретную генерацию разрешает соответствующий расход кредитов; повторно спрашивать о том же запуске не нужно. Настройка аккаунта, чтение каталога, подготовка и диагностика сами по себе такого разрешения не дают. Не запускайте платную генерацию для проверки подключения.

### Точный ID или отдельные настройки

`prepare_generation` и `generate` принимают ровно одно из полей `model` и `settings`. Для точного `model` можно добавить внешний `method`. Вместе с `settings` внешний `method` запрещен: он должен находиться внутри объекта.

```json
{
  "settings": {
    "kind": "video",
    "method": "frames",
    "family": "<EXACT_FAMILY_FROM_LIST_MODELS>",
    "durationSeconds": 8,
    "aspectRatio": "16:9",
    "resolution": "standard"
  },
  "videoWatermark": "with",
  "prompt": "<USER_PROMPT>",
  "startFramePath": "/absolute/path/start.png",
  "endFramePath": "/absolute/path/end.png"
}
```

Это аргументы подготовки. `settings` принимает только поля из примера: `kind` — `image` или `video`; `method` — `image`, `text`, `ingredients`, `frames`, `edit` или `extend`. Для изображений нужен метод `image`, для видео — остальные методы. `family` и `aspectRatio` берутся из каталога. Если `resolution` опущен, используется `standard`. `durationSeconds` обязателен для видео, кроме `edit`; для изображений и `edit` он запрещен. При редактировании длительность берется из исходного видео.

Неоднозначное или недоступное сочетание возвращает ошибку без подбора замены. При выборе через `settings` псевдонимы `veo-3.1-lite`, `veo-3.1-fast`, `veo-3.1-quality`, `omni-1.1-flash` и `omni-1.2-flash` объединяются только с вариантом `-8s-landscape` той же версии, если он есть в каталоге. Запрос через точный `model` сохраняет выбранный ID, включая прежний псевдоним. Версия 1.1 не заменяется на 1.2; неизвестные ID не подбираются по сходству.

Каталог дополнительно возвращает `generationEngine`, `family`, `methods`, `durationSource`, `resolution` и ограничения `inputsByMethod`. Для редактирования `durationSource: "input_video"`, для остальных моделей — `model`. Прежнее поле `mode` не изменилось: `references` относится к видео по образцам, `edit` — к Omni Edit, а модели изображений сохраняют `mode: "text"` при методе `image`. Обычный Omni поддерживает `text` и `ingredients`. Без явного внешнего метода точный ID Omni выбирает ингредиенты при наличии референсов, иначе текст. Явный `ingredients` требует хотя бы один референс.

Для нового видео без выбранной пользователем модели предпочтительна **Omni 1.2 Flash**; каталог отмечает предпочтение полем `preferred`. Выбирайте точный совместимый ID из текущего `list_models`, учитывая метод, длительность, формат, разрешение и роли исходников. Не выводите ID заменой `1.1` на `1.2` и не подставляйте ID Gemini API. Если совместимой Omni 1.2 нет или она недоступна, сообщите причину и возвращенный код без автоматической замены на Omni 1.1 или другую модель. Явный выбор, сохраненные настройки, история, подготовленные `generateArguments` и повтор идентичного запроса сохраняют исходную модель. Предпочтение не подтверждает поддержку backend, доступ аккаунта или право на платную проверку.

Omni 1.2 Flash поддерживает `text`, `ingredients` и `frames` на 3–15 секунд, форматы `16:9` и `9:16`, разрешение `standard` (720p) или `360p`. Для `frames` начальный кадр обязателен: на 3–10 секунд конечный необязателен, на 11–15 секунд поддерживается только начальный. Длительности 11–15 секунд требуют Google AI Pro или Ultra. Проверяйте `inputsByMethod`, `fileLimits`, `minImages`, `maxImages`, `maxVideos`, `maxReferences`, `supportsVideoReferences`, `supportsStartFrame`, `supportsEndFrame` и `requiredTier`. Наличие модели в каталоге не подтверждает доступ аккаунта. Не меняйте модель, настройки или исходники после ошибки без решения пользователя.

Варианты Veo на 4 и 6 секунд требуют Google AI Ultra; на Pro они недоступны. Варианты «По кадрам» на 8 секунд есть у Lite, Fast и Quality. Наличие модели в каталоге не гарантирует доступ аккаунта. [Официальные возможности моделей Google](https://support.google.com/flow/answer/16352836), [кадры и образцы](https://support.google.com/flow/answer/16353334).

### Текст и референсы

Пример аргументов `flow_studio_prepare_generation` для видео по ингредиентам. Замените шаблоны данными пользователя и текущего каталога; файлы должны существовать локально:

```json
{
  "model": "<MODEL_ID_FROM_LIST_MODELS>",
  "method": "ingredients",
  "prompt": "<USER_PROMPT>",
  "referencePaths": ["/absolute/path/reference.png"]
}
```

Для видео только по тексту выберите `method: "text"` и уберите `referencePaths`; этот метод не принимает исходники. Для изображения используйте `method: "image"`, референсы необязательны. Лимиты изображений: до пяти для генерации изображений, до трех для Veo по образцам и до семи для обычного Omni, с учетом более строгого лимита модели. Входные форматы: PNG, JPEG, WebP, GIF, до 20 МБ каждый. URL и base64 вместо локальных путей не принимаются.

### Редактирование исходного видео в Omni

```json
{
  "model": "<OMNI_EDIT_MODEL_ID_FROM_LIST_MODELS>",
  "method": "edit",
  "prompt": "<USER_PROMPT>",
  "videoPaths": ["/absolute/path/source.mp4"],
  "referencePaths": ["/absolute/path/style.png", "/absolute/path/subject.jpg"]
}
```

Omni 1.2 Edit использует Flow Agent в том же принадлежащем приложению браузере: точные аккаунт, модель, запрос, исходное видео и порядок изображений сохраняются. Agent готовит одно предложение на одно видео. Перед единственным Approve приложение проверяет предложение, сохраняет приватную запись отправки и проходит тот же барьер разрешенного расхода; повторного подтверждения, переключения аккаунта или платного fallback нет.

Стоимость собственного предложения Agent должна точно совпасть с расчетом для выбранного режима и целого числа секунд, округленного вверх; для Omni 1.2 секунды сверх десяти учитываются вдвойне. Предварительная проверка прямого редактора для 720p использует округление его меню, а расчет Agent — округление длительности вверх: ранее проверенный исходник 10,026667 секунды получил предложение Agent за 36 кредитов вместо 30 в прямом редакторе. Это не удвоенный бюджет и не разрешение менять модель. Совпадение стоимости не доказывает разрешение результата: перед успехом сохраняются проверки точных размеров и длительности.

Для Edit с изображениями, а также для любого Edit в 360p, приложение сначала отправляет в новой пустой сессии Agent отдельную управляющую инструкцию без вложений: использовать все изображения как ингредиенты в сохраненном порядке, сохранить следующий творческий запрос дословно, создать одно видео и не начинать генерацию или запрашивать Approve до следующего сообщения. Для 360p инструкция также фиксирует точные 360p, выбранный формат и длительность исходника, запрещает 720p, масштабирование и изменение размера; она используется и без дополнительных изображений. Затем исходное видео, необязательные изображения и неизмененный запрос отправляются отдельным сообщением. Управляющий контекст видим в Agent, не добавляется к творческому запросу и не меняет его в History. Нужны ровно одна завершенная управляющая пара сообщений и следующая собственная пара запроса/предложения; дополнительные сообщения, преждевременное разрешение или дрейф исходников отклоняются. Единственный платный барьер остается Approve после приватной записи отправки.

Для восстановления Agent запись хранит типизированный IMAGE preview исходного видео и связывает его ресурс с исходной сценой, полным запросом и упорядоченными изображениями выбранной записи History. IMAGE preview не является Google video ID; приложение не выдумывает /video/ идентификатор. Восстановление читает существующий результат, не прикрепляет исходники, не создает новое предложение и не нажимает Approve. Для поддерживаемых ошибок наблюдения после отправки приложение освобождает браузер и один раз продолжает чтение той же задачи по приватной записи отправки. Для Agent дополнительно сверяются аккаунт, проект, модель, полный запрос, исходная сцена и порядок изображений. Отмена, подтвержденный отказ или несовпадение записи блокируют этот переход. Восстановление не загружает исходники, не создает предложение или новую задачу и не нажимает Approve; нового расхода кредитов нет. Повторная ошибка наблюдения сохраняет неизвестный исход.

Omni Edit требует один путь в `videoPaths` и принимает до пяти необязательных изображений в `referencePaths`. Порядок изображений сохраняется. Для исходного видео поддерживаются MP4, MOV и M4V до 100 МиБ. Лимит `fileLimits.video.maxDurationSeconds` зависит от модели: 15 секунд для Omni 1.2 Edit, 10 секунд для Omni 1.1 Edit. Приложение загружает сам видеофайл; извлечение кадров не используется. Обычный Omni и Veo поле `videoPaths` не принимают.

Текущая фоновая реализация Omni 1.2 Edit требует точного размера исходника под выбранные формат и разрешение: 360×640 или 640×360 для 360p; 720×1280 или 1280×720 для standard (720p). Несовпадение отклоняется до загрузки: приложение не изменяет размер исходника и не подменяет модель. Для 360p приложение выбирает и проверяет 360p, формат и x1 в обычных настройках Flow до загрузки исходника и повторно перед запуском Agent. Затем отдельная управляющая инструкция фиксирует точные 360p и формат, длительность исходника и неизмененный творческий запрос, запрещая 720p, масштабирование и изменение размера. Собственное предложение Agent должно точно совпасть с расчетом выбранного режима: для наблюденного исходника 3,029333 секунды — 4 кредита при округлении вверх. Отсутствующее, неоднозначное или несовместимое предложение отклоняется до Approve. Совпадение стоимости не доказывает разрешение готового результата; размеры и длительность скачанного файла проверяются отдельно. В установленном приложении проверен непрерывный проход Omni 1.2 Edit через Flow Agent с исходным видео и двумя разными изображениями в точном порядке: полный исходный запрос, одно предложение, одно Approve за 36 кредитов, ожидание, проверка History, скачивание и сохранение без ручного восстановления. Задача завершилась за 279 секунд; MP4 — 720×1280, 9:16, H.264/AAC, 10,026667 секунды. Отдельно проверены задачи без дополнительных изображений и с двумя изображениями, восстановленные по записям отправки без новой генерации. Отдельно в установленном приложении проверен портретный Omni 1.2 Edit 360p без дополнительных изображений: одно предложение, одно Approve за 4 кредита, ожидание, скачивание и сохранение исходного MP4 360×640, H.264/AAC, 24 кадра/с, 3,029333 секунды. Задача завершилась за 219 секунд; размеры и длительность исходника сохранены. Эти проверки покрывают указанные сценарии; Edit 360p с изображениями, другие форматы и длительности не заявлены проверенными. Google может запросить отдельное согласие на права исходного видео; оно не запускает генерацию. Скачанный результат Edit подтверждается только после проверки точных размеров и длительности исходника с допуском 0,15 секунды. Если файл больше 100 МиБ или проверка недоступна, возвращается `OUTPUT_METADATA_UNAVAILABLE`; несовпадение дает `MODEL_SETTINGS_NOT_VERIFIED`. Исход остается неизвестным, автоматического повтора нет.

Лимит длительности проверяется при фактической отправке через `ffprobe` в контейнере, а не гарантируется подготовкой. FFmpeg на Mac для этого не нужен.

### Начальный и конечный кадры

```json
{
  "model": "<FRAMES_MODEL_ID_FROM_LIST_MODELS>",
  "method": "frames",
  "prompt": "<USER_PROMPT>",
  "startFramePath": "/absolute/path/start.png",
  "endFramePath": "/absolute/path/end.png"
}
```

Начальный кадр обязателен для `method: "frames"`. Конечный передается только при поддержке модели, а при `minImages: 2` он обязателен. У кадров отдельные роли: `referencePaths` не заменяет их, а конечный кадр без начального не принимается. Если роли не ясны, уточните их до расхода кредитов.

### Продолжение видео

```json
{
  "model": "<EXTEND_MODEL_ID_FROM_LIST_MODELS>",
  "method": "extend",
  "prompt": "<USER_PROMPT>",
  "sourceVideoId": "<VERIFIED_MEDIA_GENERATION_ID>"
}
```

Возьмите `sourceVideoId` из проверенного `media[index].mediaGenerationId` существующей задачи или получите ID исходного видео от пользователя. `jobId` — локальная задача Flow Studio, он не подходит. Группа референсов (`referencePaths` и, для Omni Edit, `videoPaths`), поля кадров и `sourceVideoId` взаимно исключают друг друга. Исходники другого метода отклоняются.

Во всех примерах выше вызывается подготовка без UUID и разрешения на списание. Для согласованного запуска используйте возвращенный план:

```js
const args = {
  ...plan.generateArguments,
  requestId: crypto.randomUUID(),
  confirmCreditSpend: true,
};
```

Сохраните `args` до вызова `generate`: повтор должен использовать тот же объект, UUID и неизменные файлы. Не возвращайтесь к `settings` после подготовки — `generateArguments` уже фиксирует точный ID и метод.

Перетаскивание файлов в интерфейсе не является API MCP. Агент передает абсолютные пути в соответствующих полях; к ним применяются те же нативные проверки формата и размера, что к выбору файлов и перетаскиванию. Объекты браузерного File API не принимаются.

## Проверка прежнего результата без новой генерации

Для поддерживаемых ошибок наблюдения после отправки приложение освобождает браузер и один раз продолжает чтение той же задачи по приватной записи отправки. Для Agent дополнительно сверяются аккаунт, проект, модель, полный запрос, исходная сцена и порядок изображений. Отмена, подтвержденный отказ или несовпадение записи блокируют этот переход. Восстановление не загружает исходники, не создает предложение или новую задачу и не нажимает Approve; нового расхода кредитов нет. Повторная ошибка наблюдения сохраняет неизвестный исход.

Проверка результата использует одну выбранную семантическую запись History: полный текст запроса сравнивается точно, порядок референсов и постер берутся из той же записи. Перед скачиванием эти поля повторно проверяются, а меню открывается только через собственную кнопку выбранной записи и ее aria-controls. Отсутствующая, неоднозначная или изменившаяся связь отклоняется. Этот путь проверен без новой генерации на изображении с двумя референсами, Veo 720p и восстановлении исходной задачи по записи отправки. В установленном приложении проверен непрерывный проход Omni 1.2 Edit через Flow Agent с исходным видео и двумя разными изображениями в точном порядке: полный исходный запрос, одно предложение, одно Approve за 36 кредитов, ожидание, проверка History, скачивание и сохранение без ручного восстановления. Задача завершилась за 279 секунд; MP4 — 720×1280, 9:16, H.264/AAC, 10,026667 секунды. Отдельно проверены задачи без дополнительных изображений и с двумя изображениями, восстановленные по записям отправки без новой генерации. Отдельно в установленном приложении проверен портретный Omni 1.2 Edit 360p без дополнительных изображений: одно предложение, одно Approve за 4 кредита, ожидание, скачивание и сохранение исходного MP4 360×640, H.264/AAC, 24 кадра/с, 3,029333 секунды. Задача завершилась за 219 секунд; размеры и длительность исходника сохранены. Эти проверки покрывают указанные сценарии; Edit 360p с изображениями, другие форматы и длительности не заявлены проверенными.

Для неизвестного исхода фоновой задачи используйте `flow_studio_recover_job` / CLI `recover` с единственным полем `jobId`. Приложение читает приватную запись отправки, открывает тот же аккаунт и проект, сравнивает доступный текст History, порядок ингредиентов и постер, затем скачивает выбранный результат в прежнюю запись истории. Исходники не загружаются, кнопка генерации не нажимается, новая задача и новый расход кредитов не создаются.

Вызов возвращает прежний `jobId` сразу; далее используйте обычные `wait_job` и `get_job`. Во время проверки задача имеет `status: "running"` и `recovering:true`. Успех снимает `unknownOutcome`; ошибка сохраняет неизвестный исход, кроме подтвержденного отказа Google. Отмена прекращает только чтение результата. Пауза или ручное отключение аккаунта не запрещают чтение его прежней задачи, но адрес аккаунта должен совпадать. Не переключайте аккаунты и не создавайте новый UUID.

У старых задач может не быть записи отправки: `BROWSER_RECEIPT_MISSING` означает ручную проверку той же задачи в Flow. Приложение не восстанавливает такую запись по догадке. В интерфейсе действие называется **Проверить результат в Flow**; доступность и причина сообщаются полями `recoveryAvailable` / `recoveryBlockedReason`.

## Повторы, ошибки и отмена

Тайм-аут ожидания или потеря связи не доказывают провал генерации. Сначала прочитайте задачу и историю. Если ответ на запуск потерялся, повторяйте запрос только с прежним `requestId`, теми же аргументами и неизменными исходными файлами. Оставьте `videoWatermark` опущенным, если его не было в исходном запросе. Пока задача находится среди последних 100 в истории, приложение возвращает ее вместо новой генерации.

Новый `requestId` означает новый запрос и возможное новое списание. Если старая задача уже выпала из истории, сначала выясните ее исход. Не повторяйте подтвержденно неуспешную или отмененную генерацию автоматически; не меняйте модель, текст или исходники без решения пользователя.

Задачи возвращают `generationEngine`, `accountId` и `accountEmail`, если аккаунт уже выбран, а также `retryAvailable` и причину недоступности повтора. Сводки аккаунтов включают `cooldownUntil`, `cooldownRemainingSeconds`, `cooldownResetAllowed`, `lastGenerationError` и `lastGenerationErrorAt`. После связанной с аккаунтом ошибки движок исключает его из новых запросов на 30 минут; локальные ошибки загрузки и отказы проверки содержимого не штрафуют аккаунт.

Кнопка приложения **Повторить генерацию** использует закрытый кэш исходников последних 20 задач, до 512 МиБ, сохраняет прежний аккаунт и записанный `videoWatermark`. Для новой попытки старой видеозадачи без сохраненного режима используется `"with"`. Явный ручной сброс КД доступен в приложении и через `flow_studio_reset_account_cooldown` / CLI `reset_cooldown` с единственным `accountId`, включая `PUBLIC_ERROR_UNUSUAL_ACTIVITY`. Снимается только локальный таймер; ручное отключение и последняя ошибка сохраняются. Ограничения Google не меняются; автоматический сброс после ошибки запрещен. Окончание КД не запускает новую генерацию.

Фоновый движок сохраняет неизвестный исход до единственного нажатия штатной кнопки генерации на сайте. Тайм-аут привязки новой карточки не подтверждает, была ли задача принята. Не создавайте новый UUID для автоматического обхода такого тайм-аута; сначала установите исход прежней попытки.

Сохраняйте точный текст ошибки и технический код. Пустой ответ не означает отказ модерации. `flow_studio_cancel_job` запрашивает остановку локального ожидания; задача остается `running`, пока движок не завершит работу. До отправки запрос не создается, после отправки исход может остаться неизвестным: Google мог уже принять задачу и списать кредиты.

Выход из приложения также прерывает локальное ожидание. Google может продолжить принятую задачу; проверьте ее результат в Flow перед новым запросом.

## CLI без MCP-клиента

Адаптер позволяет проверить инструменты и использовать тот же мост напрямую:

```bash
node app/mcp-server.cjs --list-tools
node app/mcp-server.cjs --call status '{}'
node app/mcp-server.cjs --call models '{"kind":"image"}'
node app/mcp-server.cjs --call models '{"kind":"video","method":"frames","durationSeconds":8,"aspectRatio":"16:9"}'
node app/mcp-server.cjs --call history '{"limit":10}'
node app/mcp-server.cjs --call isolated_inspect '{"accountId":7}'
```

В примере `isolated_inspect` замените `7` известным ID своего аккаунта. Проверка не создает генерацию.

CLI использует внутренние имена методов, например `models`, `prepare`, `job`, `wait`, `save`; MCP — имена `flow_studio_*` из таблицы. Подробнее — в [`skills/flow-studio/references/cli.md`](../skills/flow-studio/references/cli.md).

Готовая [инструкция для агента](../skills/flow-studio/SKILL.md) описывает выбор моделей, ожидание и сохранение. Ее установка зависит от вашего клиента и не заменяет подключение MCP-сервера.

Стандартные точные Veo 3.1 Lite/Fast/Quality из текущего каталога подключены к фоновому браузеру с сохранением метода text/frames/ingredients и ролей кадров. Текущий подтвержденный интерфейс аккаунта предлагает 8 секунд и 720p. Если для запрошенных 4/6 секунд нельзя подтвердить выбор Ultra, приложение возвращает `MODEL_DURATION_UNAVAILABLE` до отправки; оно не заменяет запрос на 8 секунд. Живая проверка Veo 3.1 Lite R2V 8 секунд с одним референсом завершилась успешно; другие сочетания не заявлены проверенными.
