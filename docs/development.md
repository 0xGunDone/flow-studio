# Разработка и сборка

[← README](../README.md)

Desktop-приложение рассчитано на macOS. Backend включен в репозиторий и в релизную сборку; установка не должна ссылаться на исходный каталог разработчика.

## Запуск

Нужны Node.js 22.12+, Google Chrome, Docker Desktop либо Colima с Docker CLI и Docker Compose. Для сборки используйте macOS.

1. Получите исходники:

   ```bash
   git clone https://github.com/0xGunDone/flow-studio.git
   cd flow-studio
   ```

2. Установите зависимости по lockfile:

   ```bash
   npm ci --prefix app
   ```

3. Запустите Docker Desktop либо `colima start`, затем приложение:

   ```bash
   npm start --prefix app
   ```

4. Дождитесь первого запуска движка и войдите через **Аккаунты → Войти в Google**. Для обычной работы не нужны заранее подготовленная база данных или конфигурация с секретами.

Режим разработки использует пользовательскую папку Flow Studio, как установленное приложение. Не запускайте две копии одновременно и не считайте разработку изолированной от ваших аккаунтов и истории. Перед изменениями, затрагивающими формат данных, сохраните резервную копию при закрытом приложении.

## Проверки

Проверки приложения и MCP:

```bash
npm test --prefix app
node app/mcp-server.cjs --list-tools
node --test extension/tests/*.test.cjs
node --test scripts/*.test.cjs
```

Backend использует Python и `unittest`. Для проверки backend отдельно создайте виртуальное окружение и запустите тесты из его каталога:

```bash
cd backend
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
```

Среда Python для этих тестов не нужна пользователю готового приложения: production-backend работает в контейнере. Некоторые тесты и проверки браузерного окружения могут требовать дополнительные системные зависимости; фиксируйте фактический результат, а не скрывайте пропущенные проверки.

Автоматические проверки с заглушками не подтверждают доступ Google-аккаунта или успешность платной генерации. Для ручного smoke test проверяйте запуск с чистой пользовательской папкой, вход, каталог моделей, один разрешенный пользователем запрос, экспорт результата и повторный запуск приложения. В отчете укажите архитектуру и то, что проверено вживую.

## Сборка macOS

Из корня репозитория:

```bash
npm ci --prefix app
npm run dist:arm64 --prefix app
npm run dist:x64 --prefix app
```

Обе архитектуры одной командой: `npm run dist:mac --prefix app`. Артефакты появляются в `dist/` в корне репозитория: `Flow-Studio-1.3.0-mac-arm64.zip`, `Flow-Studio-1.3.0-mac-arm64.dmg` и соответствующие файлы `x64`.

`npm run check:release --prefix app` проверяет исходники и конфигурацию упаковки. Команды сборки выполняют эту проверку, затем проверяют состав, архитектуру и ad-hoc подпись полученного `.app`. Они не публикуют артефакты автоматически.

Собирайте и проверяйте каждую архитектуру отдельно. Успешная упаковка `x64` на Apple Silicon не заменяет запуск на Intel Mac, а успешный архив не подтверждает работоспособность Docker и входа на чистом Mac.

В комплект должны входить:

- Electron-приложение и production-зависимости MCP.
- Backend с исходниками, `Dockerfile.headed` и `docker/entrypoint.headed.sh`, нужными для первого запуска.
- Лицензии приложения, Flow2API и зависимости, включая notices Electron.

Не включайте `node_modules` разработчика целиком, виртуальное окружение Python, Google-профили, `.env`, runtime-конфигурацию, базы, токены, кэш и историю генерации. Сборка должна создавать пользовательские учетные данные на машине получателя.

Сборки используют ad-hoc подпись, без Apple Developer ID и notarization. Ad-hoc подпись не означает подтвержденного Apple издателя. Не описывайте такую сборку как нотарифицированную или проверенную Apple.

## Публикация релиза

1. Согласуйте версию в `app/package.json`, lockfile, `CHANGELOG.md` и отдельном `docs/release-<version>.md`. Укажите фактически проверенные модели и ограничения; закончите обязательные живые проверки до публикации.
2. Выполните проверки исходников, приложения, расширения и backend для окончательного коммита. `npm run check:release --prefix app` проверяет состав исходников и отсутствие секретов, но не запускает Google-генерацию.
3. Соберите обе архитектуры через `npm run dist:mac --prefix app`. Скрипт проверяет архитектуру, ad-hoc подпись и состав `.app`, затем повторяет проверку после извлечения ZIP и выполняет `hdiutil verify` для DMG. После изменений исходников прежние preview-сборки нужно пересобрать.
4. Выполните `npm run dist:extras --prefix app`. Итоговый комплект содержит шесть архивов: ZIP и DMG для `arm64` и `x64`, MCP ZIP, extension ZIP, а также `SHA256SUMS.txt`. Проверьте manifest через `shasum -a 256 -c SHA256SUMS.txt` из `dist/`. Протестируйте чистый первый запуск отдельно от рабочей установки; укажите фактически проверенные платформы.
5. Зафиксируйте и отправьте проверенные исходники, дождитесь результата CI. Тег `v<version>` должен указывать на этот же коммит и совпадать с версией пакета. **Push тега `v*` автоматически запускает публикацию Alpha / Pre-release после CI и сборок**. Обычная локальная сборка ничего не публикует; ручной запуск workflow без тега только проверяет и собирает.
6. Перед push тега проверьте отдельные release notes, Chrome/Docker и Node.js для MCP, статус подписи и известные границы. Workflow публикует `docs/release-<version>.md`, шесть архивов и manifest. После публикации сравните SHA256 скачанных release assets с опубликованным manifest.

Не прикладывайте реальные данные Google для демонстрации «готового входа». Сборки распространяются без пользовательских аккаунтов.

## Архитектура

```text
Интерфейс Electron ─────┐
                       ├── Runtime / аккаунты ── локальный Flow2API ── Google Flow
MCP-клиент ── stdio ── локальный мост
```

Фоновый движок проверяет точные параметры и исходники, сохраняет неизвестный исход на диск и один раз нажимает штатную кнопку сайта Flow. Карточки существующих изображений, видео и ожидающих задач входят в базовую отметку; результат связывается с единственной новой карточкой, затем сравнивается доступный текст History и порядок референсов в деталях. Название карточки может быть автоматически сокращено Flow и не заменяет проверку исходного текста. В установленном приложении восстановлена прежняя оплаченная задача: детали подтвердили полный запрос, порядок ингредиентов и постер, после чего скачан и сохранен MP4. Обычный путь новой генерации с одним ингредиентом также проверен на Omni 1.2 Flash 3 секунды, портрет, 360p: задача прошла от отправки до скачивания и сохранения MP4. Эти две проверки не доказывают работу всех режимов или тарифов.

Проверка результата использует одну выбранную семантическую запись History: полный текст запроса сравнивается точно, порядок референсов и постер берутся из той же записи. Перед скачиванием эти поля повторно проверяются, а меню открывается только через собственную кнопку выбранной записи и ее aria-controls. Отсутствующая, неоднозначная или изменившаяся связь отклоняется. Этот путь проверен без новой генерации на изображении с двумя референсами, Veo 720p и восстановлении исходной задачи по записи отправки. В установленном приложении проверен непрерывный проход Omni 1.2 Edit через Flow Agent с исходным видео и двумя разными изображениями в точном порядке: полный исходный запрос, одно предложение, одно Approve за 36 кредитов, ожидание, проверка History, скачивание и сохранение без ручного восстановления. Задача завершилась за 279 секунд; MP4 — 720×1280, 9:16, H.264/AAC, 10,026667 секунды. Отдельно проверены задачи без дополнительных изображений и с двумя изображениями, восстановленные по записям отправки без новой генерации. Эти проверки относятся к указанному портретному сценарию 720p; остальные форматы, длительности и успешный 360p Edit не заявлены проверенными.

Backend слушает loopback-порт `38000`; мост MCP выбирает отдельный локальный порт и создает секрет подключения. Electron управляет жизненным циклом задач и сохраняет историю. Google Chrome отвечает за пользовательский вход и обновление управляемых сессий. Подробности протокола и поведения агента — в [MCP](mcp.md).

Изменения vendored backend сохраняйте вместе с тестом или описанием причины. Базовый upstream-коммит и условия лицензии зафиксированы в [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

Скачивание использует штатную кнопку Flow и вариант исходного размера выбранного разрешения. Принимаются загрузки только из собственной вкладки: канонический адрес видео Flow или объект `blob:` с origin `https://flow.google.com` и UUID. Посторонние вкладки, origin, неоднозначные загрузки, пустой файл и содержимое без MP4 `ftyp` отклоняются. Это не разрешает произвольные URL загрузки.
